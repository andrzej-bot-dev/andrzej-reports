🏆 TL;DR — da się, ale…

Krótko: automatyzacja i zdalne klikanie na iPhone — TAK (WebDriverAgent robi to lepiej niż uiautomator2). Ale "w pełni samodzielny po reboocie" — Android wygrywa wysoko. iOS postawił 3 ściany: brak wstrzykiwania dotyku przez appki, passcode po reboocie (Face ID martwy), i dialog Developer Mode po każdym reboocie.

Każda z ścian ma obejście (klawiatura BT wpisująca kod na ekranie blokady, supervision/MDM, TrollStore), więc da się złożyć działający system — ale to projekt inżynierski, nie weekendowe wdrożenie jak na Androidzie.

Najkrótsza droga dla Ciebie: skoro masz Maca M1 Pro — ścieżka 3 (Mac + iPhone Mirroring + WDA) daje 90% tego czego chcesz bez jailbreaka i bez walki. Najtańsza "pełna kontrola": używany iPhone SE2 (~500–1000 kr Blocket) + Dopamine. A jeśli celem jest po prostu "zdalny telefon do automatyzacji" — Android z poprzedniego raportu pozostaje bezkonkurencyjny.

🛠️ Ścieżka 1: Nowoczesny iPhone bez jailbreaka (np. Twoja 17e)

Stack "developer"

  • WebDriverAgent (appium fork, aktywny): serwer HTTP na telefonie (:8100) — /element/{id}/click, /touch/tap {x,y}, /screenshot, MJPEG stream, XPath-queries, lock/unlock screen (bez passcode), launch/kill apek. Napędza go XCTest = poziom systemowy, działa w każdej apce.
  • go-ios / pymobiledevice3 (z Pi5, bez Maca): instalacja i launch apek, screenshoty, syslog, crash logs, crash pull, mount Developer Disk Image/cryptex (iOS 17+ RSD tunnel). pymobiledevice3 = najbogatszy (CLI: developer mount-auto, apps launch, springboard services).
  • UxPlay na Pi5: AirPlay mirror receiver (H.264, aktywny rozwój, v1.73 marzec 2026) — obraz na żywo do przeglądarki przez ws-scrcpy-style web UI.
  • USB pairing: pierwsze "Trust" tapped raz fizycznie → potem headless reconnect po każdym reboocie (pairing record w /var/lib/lockdown + device-side permanent).
  • idevicescreenshot: działa na LOCKED ekranie (potrzebuje DDI mounted) — 1-3 s/szt → wolny "obraz" gdy telefon zablokowany.

Signowanie WDA — realne opcje

  • Free Apple ID: re-sign co 7 dni (automatyzacja możliwa z Maca: sign-wda.mjs z appium-xcuitest-driver, p12 cert)
  • $99/rok dev account: podpis roczny — koniec tematu
  • Mac M1 Pro: Xcode lokalnie = najmniej bólu

Gdzie to nie działa (uczciwie)

  • Po reboocie: wpisania kodu (klawiatura BT ✅ ale) + Developer Mode confirm (❓ niepotwierdzone obejście) + relaunch WDA (go-ios launch ✅ jeśli dev services żyją)
  • Brak Termux-odpowiednika — skrypty mogą żyć tylko na hoście (Pi/Mac), nie na telefonie
  • 17e eSIM-only: do automatyzacji nie szkodzi, do "świeżego numeru" — transfer wymaga czasu

Co bym kupił

  • iPhone SE2 (A13) ~500–1000 kr Blocket + Dopamine: sweet spot — tanio, Face ID/Apple Pay żyją, jb do iOS 18.7.1, semi-untethered re-jb z ikonki (można tapować przez WDA/TrollStore — jeśli WDA z TrollStore permanent, to relaunch po reboocie: tap tap w appce Dopamine → jb wraca → VNC/SSH wstają)
  • iPhone 7 (~750 kr) + palera1n + Project Sandcastle (Linux na telefonie! VNC/SSH natywnie, status 2026: działa dla 7/7+) — ale re-jb wymaga komputera po każdym reboocie → gorszy do unattended

Co daje jb dla remote control

  • Veency (VNC server) — musi być budowany ze source (rootless .deb nieutrzymywany), potem: pełny obraz + sterowanie z dowolnego klienta VNC (na Pi → web noVNC → Ty klikasz z przeglądarki)
  • OpenSSH/dropbear — shell na telefonie, daemony, crontab-like
  • Brak: automatyczny start tweaków po reboocie (semi-untethered = ręcznie z ikonki)

🖥️ Ścieżka 3: Mac M1 Pro jako "most" (masz go!)

  • iPhone Mirroring (macOS Sequoia+): obraz + pełne sterowanie iPhone'em z Maca, natywnie, z klawiatury/myszy — Apple-owy odpowiednik scrcpy. Wymaga: ten sam Apple ID, Continuity (bliskość WiFi/BT) → Mac stoi obok telefonu na półce.
  • Zdalny dostęp do Maca: Tailscale + RustDesk/Screen Sharing → z dowolnego miejsca na świecie widzisz Mac, a na nim iPhone. Dwa ekrany w jednym.
  • Mac robi też resztę roboty: Xcode podpisuje WDA bez 7-dniowego bólu (p12 + skrypt), Apple Configurator supervise'uje telefon (Single App Mode = apka auto-relaunch po reboocie/crashu), Fastlane/idb do automatyzacji.
  • Reboot iPhone w tej ścieżce: klawiatura BT (sparowana z IPHONE, nie Maciem — może być ta sama fizyczna? nie — potrzebna osobna lub emulacja) wpisuje kod; Developer Mode confirm nadal otwarty problem do testu.
  • Ograniczenie: iPhone Mirroring nie działa przez internet sam z siebie (Continuity proximity) — dlatego Mac musi być fizycznie obok telefonu.

Uwaga: iPhone Mirroring = funkcja macOS 15+/iOS 18+; Mac M1 Pro z Sequoia+ → spełnia. Dawid: masz M1 Pro (memory plugin Jun 2026: Feather/uYou sideload).

🔄 Co dokładnie dzieje się z iPhone po reboocie (mapa)

  1. Telefon sam wstaje po podpięciu zasilania (sprzętowo, wszystkie modele — MacRumors: "firmware BLE dla Find My gdy off")
  2. Ekran blokady czeka na passcode (Face ID martwy do 1. unlocku) → klawiatura BT (sparowana WCZEŚNIEJ!) wpisuje kod — każda klawiatura budzi ekran, "hit any key"
  3. USB accessory access: iOS 16+ domyślnie blokuje USB na locked — ustawione raz "Allow Accessories When Locked" (albo odblokowane przez klawiaturę)
  4. Pairing trust z Pi/Mac: przetrwał (raz nadany, permanent do factory reset)
  5. Developer Mode: może pokazać confirm dialog → test na 17e; ewentualnie supervision/MDM to wyłącza
  6. WDA: nie żyje → go-ios/pymobiledevice3 launch ponownie (jeśli dev services OK)
  7. Shortcuts automations: przetrwały reboot, time-of-day trigegery odpalają się same (bez potwierdzeń po jednorazowym "Enable")
  8. Supervised Single App Mode: apka wraca sama, pełny ekran, auto-relaunch po crashu

🚀 Co bym wdrożył (rekomendacja)

  1. Test krytyczny na Twojej 17e (30 min, zanim wydasz złotówkę): włącz Developer Mode → reboot → sprawdź czy confirm dialog faktycznie blokuje dev services (go-ios launch WDA). Jeśli tak i nie da się go okrążyć supervisionem → ścieżka "17e unattended" umiera i zostają ścieżki 2/3.
  2. Jeśli chcesz iPhone do zdalnej roboty: SE2 z Blocket (~700 kr, sprawdź Find My OFF i iOS ≤18.7) + Dopamine + Veency (build z source) + SSH. Budżet czasu: dzień roboty.
  3. Jeśli chcesz sterować SWOJĄ 17e zdalnie: Mac M1 Pro na półce obok + iPhone Mirroring + Tailscale/RustDesk do Maca. Zero ryzyka, zero jb, działa dziś. (Werdykt: to nie jest "unattended phone farm" — to "remote control Twojego telefonu". Inny cel, inna droga.)
  4. Jeśli cel = automatyka 24/7 (boty, farmy, apki): wracamy do Androida z raportu #1. iOS do tego nie służy — Apple wygrywa w prywatności, przegrywa w programowalności.
