⚠️ Znane problemy

🔥 Przegrzewanie (55–65°C)

OV5640 pobiera więcej prądu niż OV2640 (ok. 300–350 mA przy full-res). Przy dłuższej pracy temperatura modułu sięga 55–65°C, co może powodować artefakty i niestabilność. ESP32-CAM nie ma radiatora – zaleca się pasywne chłodzenie lub obniżenie rozdzielczości.

→ Test temperatury (YouTube) ↗

📶 Pionowe linie / szum (Vertical Lines)

Na niektórych płytkach (szczególnie ESP-EYE) OV5640 generuje pionowe linie i szum w obrazie JPEG. Problem nie znika przy zmianie XCLK (5/10/15/20 MHz). Prawdopodobnie wynika z zakłóceń na liniach DVP lub problemów z zasilaniem.

→ GitHub Issue #172 ↗

🐌 Niski FPS na pełnej rozdzielczości

Mimo że sensor wspiera 15 fps przy UXGA, na ESP32 realny framerate spada do 4–6 fps z powodu ograniczeń przepustowości ESP32. OV2640 osiąga lepsze FPS (12 fps UXGA) przez prostszy format transmisji. Przy 720p OV5640 osiąga ~25 fps.

→ GitHub Issue #201 ↗

🟢 Zielono-niebieski odcień (Tint)

Po restarcie niektóre egzemplarze OV5640 pokazują zdjęcia z zielonym lub niebieskim odcieniem. Problem występuje losowo, może być związany z inicjalizacją balansu bieli (AWB) w sterowniku esp32-camera.

→ GitHub Issue #314 ↗

⏱️ Timeout przy przechwytywaniu klatki

Błąd „esp_camera_fb_get(): Failed to get the frame on time!" – częsty przy wyższych rozdzielczościach (UXGA, QXGA) gdy ESP32 nie nadąża z odbiorem danych z sensora. Rozwiązaniem jest zmniejszenie rozdzielczości lub zwiększenie bufora.

→ GitHub Issue #155 ↗
