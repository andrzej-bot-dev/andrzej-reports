🏆 TL;DR — werdykt

Nie potrzebujes żadnej "farmy". Jeden telefon + kabel USB do Pi5 + stack scrcpy/autoadb + uiautomator2 + Tailscale = pełna zdalna kontrola i automatyzacja, która sama wstaje po reboocie telefonu. Koszt software: 0 kr.

Kluczowa architektura (zero roota):

  • 🔌 Telefon kablem USB na stałe do Pi5 — ADB po USB reconnectuje się sam po reboocie telefonu ("always allow" zapamiętane). Po WiFi by się rozpadało (port się zmienia).
  • 🖥️ scrcpy + autoadb na Pi5 (systemd) — jak telefon wraca, okno/scrcpy wstaje automatycznie.
  • 🌐 ws-scrcpy w Dockerze na Pi5 — Ty klikasz telefon z przeglądarki (przez Tailscale, z dowolnego miejsca na świecie). Zero auth → trzymać tylko w LAN/Tailscale.
  • 🤖 Ja (Andrzej) steruję telefonem z Pi przez uiautomator2 (Python): klik, swipe, screenshot, XPath, instalacja APK — bez roota. Mogę robić na telefonie to co na Chrome.
  • 🔓 Telefon bez PIN-u (swipe) — twardy warunek bez roota: żadne narzędzie świata nie odblokuje ekranu po reboocie. Za to scrcpy/ADB działają NA ekranie blokady (można even wpisać kod — ale przy braku PIN-u problem znika).
  • ⚡ Telefon, który sam wstaje po podaniu zasilania (domyślne zachowanie PMIC u większości marek) + smart plug jako "twardy reset" awaryjny.

Telefon: jeśli masz Wolne urządzenie — użyj go. Jak kupować: używka 500–1500 kr (Blocket/FB), najlepiej z natywnym limitem ładowania (Samsung "Protect Battery" 85%, Motorola 50/80%, Xiaomi 85%, OnePlus 80/85%) — bo telefon będzie na kablu 24/7.

📦 Co Dawid zobaczył: "Boxphone farm"

Box Phone Farm = skrzynia (chassis) z wieloma płytami głównymi telefonów (nie kompletnymi telefonami), wspólnym zasilaczem, chłodzeniem i USB hubem → jedno PC kontrolne steruje wszystkim. Popularne w SMM/MMO (masowe prowadzenie kont TikTok/IG/FB).

  • Skład: chassis + mainboardy + centralny PSU + wentylatory + USB hub + PC kontrolny + software + proxy per urządzenie (GenRouter) — bez proxy wykrywalne od ręki
  • Ceny AliExpress (sama skrzynia, bez telefonów): 20-port ~578–912 kr, 60-port ~2600–3100 kr; cały zestaw 20 szt. ~10–20 tys. kr
  • Ecosystem GenFarmer: box + cloud dashboard + proxy + GenLogin (anti-detect browser) — model biznesowy = abonamenty
  • Sterne software farm: GenFarmer Platform (subskrypcja), Total Control (komercyjne, do 100 urządzeń), Sonic Cloud, 群控 (group control) — wszystko po to, żeby JEDEN operator kliknął raz na 50 telefonów

Wniosek dla Ciebie: 100% tego hardware'u jest zbędne przy 1 telefonie. Z farmy potrzebujesz tylko warstwy software'owej: mirror + kontrola + skrypty — a to daje za darmo scrcpy/QtScrcpy + uiautomator2. Nawet ryzyko bana jest przy 1 urządzeniu dużo mniejsze (algorytmy celują w koordynowane sieci urządzeń/proxy).

🔧 Rekomendowany stack (dwie warstwy dostępu)

Warstwa 1: "Ja klikam" — automatyzacja z Pi (Andrzej → telefon)

  • adb (USB) — połączenie przez kabel do Pi5. Po reboocie telefonu: host ADB sam wykrywa urządzenie (klucz autoryzacji trwały). Xiaomi/Samsung mają dodatkowy "USB debugging (security settings)" — zatwierdzić raz.
  • uiautomator2 (Python, openatx) — d.xpath('//*[@text="Login"]').click(), screenshot, swipe, install, dump UI, app_start. Bez roota. HTTP JSON-RPC na :9008 przez adb forward.
  • screencap / input / am — czysty adb shell fallback: input tap, input keyevent, am start -a android.intent.action.VIEW -d URL, screencap -p → ja widzę i klikam jak w browserze.
  • STFService.apk (Google/openstf) — dodatkowe: KeyGuard unlock/relock, rotacja, wakelock, battery stats, IMEI (poziom uprawnień ADB, nie root).

Warstwa 2: "Ty klikasz" — zdalny pilot dla Dawida

  • ws-scrcpy (Docker na Pi5, port :8000) — telefon w przeglądarce, klikanie myszą, klawiatura, MSE/WebCodecs decode. Otwierasz z telefonu/laptopa przez Tailscale z dowolnego miejsca. ⚠️ Brak wbudowanego auth → dostęp tylko z Tailscale/LAN (nginx auth opcjonalnie).
  • scrcpy + autoadb (rom1v, autor scrcpy) — systemd na Pi5: autoadb scrcpy -s '{}' → po każdym powrocie urządzenia mirror wstaje sam. Do lokalnego użytku na Pi/desktop.
  • RustDesk (opcja premium) — pełny "TeamViewer-grade" remote control, self-hosted serwer hbbs/hbbr w Dockerze na Pi5 (arm64 OK), E2E encryption, darmowy AGPL. Android host: permanent password + accessibility input + battery unrestricted. Po reboocie wymaga workaroundu (MacroDroid auto-klik MediaProjection consent) — dlatego głównym kanałem pozostaje ws-scrcpy, a RustDesk jako wygodny dodatek.

Źródła: github.com/NetrisTV/ws-scrcpy, github.com/aivus/docker-ws-scrcpy-rpi, github.com/rom1v/autoadb, rustdesk.com/docs/en/self-host/rustdesk-server-oss/docker, github.com/openatx/uiautomator2

⚔️ Wariant A (bez roota) vs Wariant B (z rootem)

Wariant A — bez roota (rekomendowany start)

  • Swipe lock (bez PIN), SIM bez PIN
  • USB → Pi5, adb authorized, autoadb + ws-scrcpy (Docker) + Tailscale
  • uiautomator2 z Pi = automatyzacja
  • MacroDroid ($5, albo free do 5 makr): boot → wake screen, re-enable różnych rzeczy; webhook listener wbudowany (HTTP na telefon!)
  • Termux + Termux:Boot + sshd: pełny shell NA telefonie po SSH, skrypty cron-like, przeżywa reboot
  • Auto power-on: większość telefonów włącza się sama po podpięciu ładowarki (PMIC) → smart plug = zdalny hard-reset
  • Koszty: 0 kr software (MacroDroid optional $5)

Wariant B — z rootem (gdy A nie wystarczy)

  • Magisk v30.7 (aktywny, Feb 2026, Android 16 support)
  • Persistent adb tcpip 5555 (init.rc/Magisk module) — ADB po WiFi bez USB
  • lock_screen_disabled 1 — telefon bez żadnej blokady
  • Pełny Shizuku persist, minicap na Android 10+
  • Uwaga: Samsung = Knox tripped raz na zawsze (OK dla dedykowanego telefonu); banking apps wymagają pełnego hiding stacku (Zygisk + DenyList + safetynet-fix + props config) i i tak nie ma gwarancji
  • Bootloader unlock: Xiaomi (okres oczekiwania), Pixel (najłatwiej), Samsung (Knox), Motorola (łatwo)

Kiedy root? Tylko jeśli potrzebujesz: PIN na telefonie, WiFi-ADB bez kabla, albo deep integracji. Na start — A wystarczy w 95%.

🔋 Zdrowie telefonu 24/7 (żeby nie spuchła bateria)

  • Limit ładowania OBOWIĄZKOWO: Samsung "Protect Battery" (85%) · Motorola "Protect Battery" (50/80%) · Xiaomi/HyperOS (85%) · OnePlus "Charging Limit" (80/85%). Pixel: brak natywnego (Android 16 może dodać) → gorszy kandydat. Przy stałym 100% bateria puchnie realnie po 12–18 mies.
  • Termika: bez etui, przewiewne miejsce, ambient <30°C; USB wiatraczek jeśli >38°C sustained.
  • Reboot higieniczny raz w tygodniu (memory leak cleanup) — ja mogę robić przez adb reboot w cronie i sam sprawdzać powrót.
  • Auto power-on po zaniku prądu: większość telefonów włącza się sama gdy pojawia się ładowarka (PMIC, default). Przetestować PRZED zakupem używki (podpiąć zasilanie do wyłączonego telefonu). Smart plug (Zigbee/Tapo) na telefon = zdalny hard reset z aplikacji.
  • NAND/heat: niższy SoC = dłuższe życie flash; kolejny argument za charge limit.

Źródła: r/Android wątki battery, XDA, per-brand docs (distillat boot-persistence.md, strony 10-16)

🚀 Plan wdrożenia (po dostarczeniu telefonu)

  1. Telefon: używka (Samsung A/Moto G/Xiaomi Redmi z charge limit), reset fabryczny, konto Google throwaway. Bez PIN, SIM bez PIN. Developer options: USB debugging ON + "always allow" z Pi, USB debugging (security settings) jeśli OEM wymaga.
  2. Battery: limit 80/85%, battery optimization OFF dla: Termux, MacroDroid, RustDesk (jeśli), autostart ON.
  3. Kabel: dobry kabel USB-A→C do Pi5 (data!), port stały.
  4. Pi5: apt install adb scrcpy (albo build z source dla v4.1) → adb devices autoryzacja.
  5. systemd: autoadb scrcpy -s '{}' --no-audio jako serwis użytkownika (mirror awaryjny).
  6. Docker: ws-scrcpy (obraz aivus/docker-ws-scrcpy-rpi) → port 8000, dostęp TYLKO przez Tailscale (brak auth!).
  7. Python: venv + pip install uiautomator2 → test: screenshot, tap, xpath.
  8. Termux na telefonie: sshd + Termux:Boot + skrypty startowe.
  9. Watchdog: cron na Pi co 2 min: adb get-state; jak device offline >5 min → notify Discord (#automatyzacja) + opcjonalnie smart plug cycle.
  10. Test końcowy (drill): adb reboot → mierzymy czas do pełnej dostępności (oczekiwanie: 30-90 s) → ws-scrcpy działa, uiautomator2 działa. ✅

Estymata: 1–2 h roboty na wdrożenie. Wszystko na moim Pi już prawie jest (Docker, Tailscale, cron, notify).
